# 俺の秘書子 — 設計書

最終更新: 2026-09-04

## 1. 概要

### 目的
汎用的な業務能率化デスクトップアプリ。特定の会社・特定業務に依存しない機能を、
必要に応じて追加していける「機能プラグイン方式」で作る。

第1機能は **メール文面作成**。Claude API を使い、場面（御礼・謝罪・日程調整など）と
宛先・件名・一言メモを入力するだけで、その場面にふさわしいビジネスメールの文面を生成し、
Outlook または Gmail の**下書き**として開く。

### 既存アプリ TaskHelper との関係
TaskHelper（人事労務業務に特化した Electron アプリ）を**構成の参考元**とする。
以下を流用する（TaskHelper 側のファイルは一切変更しない）。

| 流用元 | 用途 |
|---|---|
| `electron/main.js` / `preload.js` | Electron の起動・IPC の骨格 |
| `src/main/settings.js` | 設定の永続化パターン |
| `src/main/outlook-send.ps1` | Outlook COM 操作（**送信ではなく下書き表示**に改造） |
| `package.json` の `build` セクション | electron-builder（nsis インストーラ / portable exe）設定 |

TaskHelper 固有の業務ロジック（有休・出勤率・残業・名簿など）は**一切持ち込まない**。

### 技術スタック
- Electron 33 + Node.js（TaskHelper と同一）
  - app-package-flow の既定である Python + Tkinter からの逸脱。理由は Outlook 連携資産の
    流用と UI 表現力。ユーザー承認済み。
- Claude API（Anthropic Messages API）
- electron-builder（nsis インストーラ + portable exe）
- テスト: `node --test`（Node 標準テストランナー）

### リポジトリ
https://github.com/kamaboko3473150buta-ux/orenohisyoko （**公開リポジトリ**）

公開リポジトリであるため、APIキー・宛先・作成した文面などの機密情報は
**リポジトリに一切含めない**。これらはすべて実行 PC のユーザープロファイル配下に保存する。

### 2-2b. 返信文作成 — 入力画面

受信したメールを貼り付けるだけで返信文を作る。**宛先・件名・場面の入力は不要**
（すでにメーラーで「返信」を押している前提なので、宛先も件名も入っている）。

```
+--------------------------------------------------------+
|  <- 戻る    返信文を作成                     [ 設定 ]  |
+--------------------------------------------------------+
|  (1) 受信したメールを貼り付け                          |
|   +----------------------------------------------+    |
|   | （相手から届いたメールの本文をそのまま貼る） |    |
|   +----------------------------------------------+    |
|                                                        |
|  (2) 文体  [ かしこまった社外向け v ]                  |
|                                                        |
|  (3) 伝えたいこと（任意・空欄でよい）                  |
|   [ 例: 今回は断りたい／来週なら可能               ]   |
|                                                        |
|                    [ 返信文を作成する ]                |
+--------------------------------------------------------+
```

- 受信メールが空のときは生成せず、赤枠とメッセージを出す（API は呼ばない）。
- (3) は任意。承諾か辞退かなど、受信メールだけでは判断できない場合にだけ書いてもらう。
- **出口はクリップボードへのコピー**。下書きは開かない
  （すでに返信画面を開いているので、そこに貼れば済むため）。

### 2-5. タスク・スケジュール管理

予定（日時のある約束）とタスク（期限のあるやること）を**1つのリスト**で扱う。
日時があれば予定、期限だけならタスクとして表示し分ける。

```
+--------------------------------------------------------+
|  <- 戻る   タスク・スケジュール管理          [ 設定 ]  |
+--------------------------------------------------------+
|  [ 来週金曜までにA社へ見積書を送る          ] [ 追加 ] |
|   話し言葉のまま入力 -> AIが期限・相手・種別を推定      |
|   ( )AIで取り込む  (o)手で入力する                     |
|                                                        |
|  ● 期限切れ (1)                                        |
|     [ ] 請求書の確認        9/2 まで    A社            |
|  ● 今日 (2)                                            |
|     [ ] 定例会議            14:00                      |
|     [ ] 見積書を送る        今日まで    B社            |
|  ● 明日 (1)  ● 今週 (3)  ● それ以降 (2)  ● 期限なし(2)|
|  > 完了したもの (12)                                   |
|                                                        |
|              [ 今日の進め方を相談する ]                |
+--------------------------------------------------------+
```

- **取り込み**: 1行の自然文を Claude が構造化する。**登録前に必ず確認画面を出す**
  （誤読をそのまま登録しないため）。読み取れなかった項目は空欄のまま出す。
- **手入力**: API を使わずフォームから直接登録する。ラジオで切り替え、選択は記憶する。
- グループは「期限切れ／今日／明日／今週／それ以降／期限なし／完了」。
  完了は折りたたみ、既定は閉じた状態。
- 並び順はグループ内で「時刻あり→時刻順、次に優先度、次に登録順」。
- 期限切れは赤、今日は強調して表示する。
- チェックで完了/未完了を切り替え、項目をクリックすると編集・削除ができる。

### 2-6. 秘書子の吹き出し（全画面共通）

全画面の**右下に常駐**し、場面に応じて表情と一言が変わる。クリックで折りたためる
（入力に集中したいときに邪魔にならないようにする）。折りたたみ状態は記憶する。

```
                                  +---------------------+
                                  | 今日は3件、うち1件が |
                                  | 締切です            |
                                  +--------------v------+
                                        ( 秘書子 )
```

| 場面 | 表情キー | 例 |
|---|---|---|
| 通常・待機 | `normal` | 「今日は3件、うち1件が締切です」 |
| 作成中 | `thinking` | 「文面を考えています…」 |
| 完了 | `smile` | 「できました。確認してくださいね」 |
| エラー | `trouble` | 「APIキーを確認していただけますか」 |
| 締切が近い | `hurry` | 「A社の見積書、今日までです」 |
| タスク完了時 | `praise` | 「おつかれさまです」 |

- 画像は `assets/hishoko/<表情キー>.png`。**画像が無い場合は吹き出しだけを表示**し、
  あとから画像を置くだけで有効になる（読み込み失敗時は画像要素を隠す）。
- electron-builder の `files` に `assets/**` を含めること（`assets/icon.ico` だけでは同梱されない）。

### 2-7. 資料作成

**構成案を確認してから本文を作る2段階**にする。長い資料で構成が意図と違ったとき、
全部作り直しになるのを避けるため。

```
+--------------------------------------------------------+
|  <- 戻る   資料作成                          [ 設定 ]  |
+--------------------------------------------------------+
|  (1) 資料の種類                                        |
|  [プレゼン] [レポート] [議事録] [社内文書] [引継ぎ]    |
|                                                        |
|  (2) 何を作りたいか                                    |
|   +----------------------------------------------+    |
|   | 9/3の定例会議の議事録。決定事項と宿題を明確に |    |
|   +----------------------------------------------+    |
|                                                        |
|  (3) 参考資料（複数可）          [ ファイルを選ぶ ]    |
|   文字起こし.txt        12,400字                  [x]  |
|   前回議事録.docx        3,200字                  [x]  |
|   ------------------------------------------------     |
|   合計 15,600字 / 概算 約48円                          |
|                                                        |
|  (4) 出力形式  (o)Word  ( )PowerPoint  ( )PDF          |
|                                                        |
|                  [ 構成案を作る ]                      |
+--------------------------------------------------------+
```

構成案の画面では、見出し（プレゼンならスライド）の一覧を出し、
**文言の修正・並べ替え・削除**ができる。確定したら本文を作る。
本文はプレビューで編集でき、そのあと保存ダイアログでファイルに書き出す。

- 読み取れなかった添付は、その旨を一覧に出して**他の資料だけで続行**できるようにする
  （1つ読めないだけで作業全体が止まらないようにするため）。
- 出力形式の初期値は種類で決まる（プレゼン→PowerPoint、それ以外→Word）。

## 4. データ設計

### 4-1. 保存場所
`%APPDATA%\ore-no-hishoko\`（Electron の `app.getPath('userData')`）

exe にもリポジトリにも含まれない。別PCにアプリを配っても中身は引き継がれない。

### 4-2. `settings.json`

```json
{
  "apiKeyEncrypted": "<base64: safeStorage で暗号化した文字列>",
  "signature": "株式会社△△ 総務部\n松原 太郎\nTEL: ...",
  "defaultTone": "formal_external",
  "defaultMailer": "outlook"
}
```

APIキーは Electron の `safeStorage`（Windows の DPAPI）で暗号化して保存する。
`safeStorage` が使えない環境では、その旨を警告したうえで平文保存にフォールバックする。

### 4-3. `contacts.json`（宛先履歴）

```json
[
  {
    "email": "yamada@example.com",
    "company": "株式会社○○",
    "department": "営業部",
    "name": "山田 太郎",
    "honorific": "様",
    "lastUsedAt": "2026-09-04T10:00:00.000Z"
  }
]
```

同一メールアドレスは上書き。最終使用日時の降順で最大100件保持。

### 4-4. `history.json`（文面履歴）

```json
[
  {
    "id": "2026-09-04T10:00:00.000Z",
    "scene": "thanks",
    "tone": "formal_external",
    "to": "yamada@example.com",
    "subject": "お打ち合わせの御礼",
    "body": "……",
    "createdAt": "2026-09-04T10:00:00.000Z"
  }
]
```

新しい順に最大100件。超えたら古いものから捨てる。
返信文作成で作ったものは `scene: 'reply'` で保存し、履歴から開くと返信モードのプレビューになる。
**貼り付けた受信メールそのものは保存しない**（他人の個人情報を溜め込まないため）。

### 4-4b. `usage.json`（API利用状況）

```json
{
  "2026-09": { "count": 12, "inputTokens": 12000, "outputTokens": 9000 }
}
```

月ごとに、生成した通数と入力・出力トークン数を積み上げる。金額は保存せず、表示のたびに計算する。

概算金額 = 入力トークン ÷ 100万 × $5 ＋ 出力トークン ÷ 100万 × $25（`claude-opus-5` の料金）。
円換算は固定レートを使う。**あくまで目安**であり、実際の請求額とは一致しない
（プロンプトキャッシュや失敗した呼び出しなどを含まないため）。画面にもその旨を表示する。
**モデルを変えたら `src/main/usage.js` の料金定数も直す。**

### 4-5. Claude API 呼び出し

公式 SDK **`@anthropic-ai/sdk`** を使う（生の HTTP は書かない）。Electron のメインプロセス
（Node 側）から呼ぶ。レンダラー（画面）側には APIキーを一切渡さない。

| 項目 | 値 | 理由 |
|---|---|---|
| モデル | `claude-opus-5` | 日本語ビジネス文書の品質を優先。`src/main/claude.js` の定数1行で変更できる |
| `max_tokens` | 4000 | メール1通には十分。切り詰められる心配がない |
| `output_config.effort` | `low` | メール作成は単純なタスク。低くすることで応答が速く・安くなる |
| `thinking` | 指定しない | Opus 5 は既定で adaptive。短文生成では指定不要 |
| タイムアウト | 60秒 | SDK の `timeout` オプション（ミリ秒指定なので `60000`） |

- system プロンプト: 「日本のビジネスメールを書く秘書」としての役割・出力形式の指示
- user プロンプト: 場面・宛先・件名・一言メモ・文体を埋め込んだテンプレート
- 出力形式: **本文のみのプレーンテキスト**（前置き・解説・マークダウンは出力させない）。
  Opus 5 以降では assistant プレフィル（返答の書き出しを指定する手法）が使えないため、
  出力形式の制御は system プロンプトで行う。
- 署名はアプリ側で本文末尾に連結する（AI には書かせない）
- レスポンスは `response.content` の配列から `type === 'text'` のブロックを取り出す
- `response.stop_reason === 'refusal'` の場合は本文が空になるため、
  「この内容では文面を作成できませんでした。書き方を変えてお試しください」と表示する

**費用の目安**: 1通あたり入力約1,000トークン・出力約800トークン。
Opus 5 は入力 $5／出力 $25（各100万トークン）なので、**1通あたりおよそ4円**。

### 4-6. Gmail 下書きの開き方

```
https://mail.google.com/mail/?view=cm&fs=1&to=<宛先>&su=<件名>&body=<本文>
```

各値は `encodeURIComponent` でエスケープし、`shell.openExternal` で既定ブラウザに渡す。

URL 全長が 8000 文字を超える場合は、ブラウザ側で切れる恐れがあるため、
本文をクリップボードにコピーしたうえで宛先・件名だけの URL を開き、その旨を画面に表示する。

### 4-7. Outlook 下書きの開き方

`draft-outlook.ps1` に JSON（宛先・件名・HTML本文）を渡し、Outlook COM で
`CreateItem(0)` → プロパティ設定 → **`.Display()`**（送信はしない）。
TaskHelper の `outlook-send.ps1` から `.Send()` を除いた形。

**`.ps1` は必ず UTF-8 BOM 付きで保存すること。** Windows PowerShell 5.1 は BOM の無いファイルを
ANSI（Shift-JIS）として読むため、日本語コメントが壊れて構文エラーになる。
実際にこれで下書きが開けない不具合が起きた。`test/draft.test.js` に先頭3バイトを検査する
回帰防止テストを置いてある。

### 4-4c. `tasks.json`（タスク・スケジュール）

```json
[
  {
    "id": "2026-09-04T10:00:00.000Z-a1b2",
    "title": "A社へ見積書を送る",
    "due": "2026-09-12",
    "at": "14:00",
    "who": "A社 山田様",
    "kind": "提出",
    "priority": "normal",
    "note": "",
    "done": false,
    "createdAt": "2026-09-04T10:00:00.000Z",
    "doneAt": null
  }
]
```

- `due` は日付のみ（`YYYY-MM-DD`）、`at` は時刻のみ（`HH:MM`）。どちらも任意。
  `at` があるものを「予定」、`due` だけのものを「タスク」として表示する。
- `kind` は「提出／連絡／会議／移動／その他」を想定するが、自由文字列も許容する。
- `priority` は `high` / `normal` / `low`。
- 完了したものは最新100件まで保持し、それより古いものは捨てる。
- グループ分けは表示のたびに**その日の日付を基準に計算**する（保存はしない）。

### 4-5b. タスクでの Claude API 呼び出し

どちらも短いやり取りで、1回あたりおよそ1円前後。

| 用途 | 入力 | 出力 |
|---|---|---|
| 取り込み | 話し言葉1行＋今日の日付 | `title` `due` `at` `who` `kind` `priority` を持つ JSON |
| 今日の案内 | 未完了の一覧（件名・期限・優先度）＋今日の日付 | 2〜4文の日本語の提案 |

- 取り込みは **JSON のみを返すよう system プロンプトで指示**し、
  コードフェンスが付いていても取り除いてから `JSON.parse` する。
  解析に失敗した場合は、入力文をそのまま `title` に入れた項目として扱い、その旨を画面に出す
  （API 料金を払ったのに何も残らない、という事態を避けるため）。
- **今日の日付を必ずプロンプトに含める**。「来週金曜」のような相対表現を解決できないため。
- 案内は表示するだけで、タスクの中身は書き換えない。

### 4-4d. 資料の中間形式

生成した資料は、出力形式によらない共通の形にしてから各ファイルに書き出す。
これにより「Word で作ったものを PDF でも出す」が同じデータでできる。

```json
{
  "title": "第12回 定例会議 議事録",
  "sections": [
    {
      "heading": "決定事項",
      "paragraphs": ["……"],
      "bullets": ["A案で進める", "予算は来月確定"]
    }
  ]
}
```

- プレゼンでは 1 section = 1 スライド、`heading` がスライドタイトル、
  `bullets` が箇条書き、`paragraphs` はノート的な補足として扱う。
- 保存はしない（作るたびに使い捨て）。作った資料はファイルとして書き出す。

### 4-5c. 資料作成での Claude API 呼び出し

**2回に分ける**。構成案と本文で求めるものが違い、長い資料では一度に出しきれないため。

| 用途 | 入力 | 出力 |
|---|---|---|
| 構成案 | 種類・何を作りたいか・参考資料の本文・今日の日付 | `{ title, sections: [{ heading, points }] }` の JSON |
| 本文 | 上記＋確定した構成 | 4-4d の中間形式の JSON |

- どちらも **JSON のみを返すよう system プロンプトで指示**し、コードフェンスが付いていても
  取り除いてから `JSON.parse` する。失敗しても例外は投げず、画面にその旨を出す。
- **参考資料に無いことを創作させない**。不明な点は ［ ］ の空欄にするよう指示する。
- 議事録では「決定事項」「宿題（誰が・いつまでに）」を必ず立てるよう、種類ごとの指示を持たせる。

### 4-6. 費用の概算

添付した参考資料はそのまま API に渡るため、**メール作成（1通4円）とは桁が違う**。
A4で20ページ相当を添付すると1回あたり50〜100円になり得る。

- 添付した時点で**文字数の合計と概算金額**を画面に出す。
- 日本語はおおむね1文字≒1トークンとして、安全側（多め）に見積もる。
- **3万字を超えたら、実行前に確認ダイアログを出す**（意図しない高額課金を防ぐため）。
- 構成案と本文で2回呼ぶので、概算は2回分として示す。

**費用の内訳で効くのは出力側**。出力の単価は入力の5倍で、
出来上がる資料の分量は参考資料の大きさに比例しない（A4数枚に収まる）。
そのため **参考資料が無くても1回あたり25〜30円かかり**、参考資料が増えた分だけ緩やかに上がる。

| 参考資料の合計 | 概算 |
|---|---|
| なし〜1,000字 | 約27円 |
| 15,000字 | 約48円 |
| 30,000字（確認が出る境目） | 約70円 |
| 60,000字 | 約115円 |

概算を出力＝入力と同数で見積もると3〜5倍に膨らみ、使うのをためらわせてしまう。
出力側は固定値（構成案1,200・本文5,000トークン）で見積もること。

## 5. エラー処理方針

| 状況 | 画面の挙動 |
|---|---|
| APIキー未設定 | 「文面を作成する」を押した時点で案内を出し、設定画面へ誘導する |
| APIキーが無効（401） | 「APIキーが正しくないようです。設定を確認してください」 |
| 利用上限・残高不足（429/402） | 「Anthropic 側の利用上限に達している可能性があります」 |
| 通信できない | 「インターネットに接続できませんでした」＋再試行ボタン |
| API がタイムアウト（60秒） | 「時間内に応答がありませんでした」＋再試行ボタン |
| 必須項目が空（宛先メール・件名・メモのいずれか） | 生成前に該当欄を赤枠で示し、API は呼ばない |
| Outlook がインストールされていない | 「Outlook が見つかりません」＋ Gmail で開く／コピーする を提案 |
| Gmail の URL が長すぎる | 本文をコピーしたうえで宛先・件名のみの作成画面を開き、貼り付けを案内 |
| 設定ファイルが壊れている | 既定値で起動し、「設定を読み込めなかったため初期化しました」と表示 |

APIキーはログにも画面のエラー文にも**絶対に出力しない**。

## 6. 制約・注意事項

- **Windows 専用**。Outlook 連携は Windows の Outlook classic デスクトップ版が前提。
- **送信はしない**。アプリは下書きを開くところまで。送信操作は必ず人間が行う。
- **API 利用料はユーザー負担**。1通あたりおおむね数円以下だが、無制限ではない。
- **公開リポジトリ**のため、APIキー・実在の宛先・実際の文面をコミットしない。
  `.gitignore` で `dist/`・`node_modules/`・`*.log`・`.env` を除外する。
- **資料作成の出力は完成品ではなく下地**。特に数値・日付・固有名詞は必ず人が確認する。
- **Outlook 予定表との連携はしない**（会議の自動取り込み）。認証と同期の設計が一段重くなるため、
  今回の範囲から外す。将来の拡張候補として残す。
- 生成された文面は**必ず人間が確認してから送る**。AI が事実を取り違える可能性がある。
- コード署名をしていないため、配布先PCで SmartScreen 警告が出る（「詳細情報」→「実行」で起動可）。

## 7. テスト方針

外部（API・Outlook・ブラウザ）に依存しないロジックだけを `node --test` で自動テストする。

| 対象 | 確認内容 |
|---|---|
| プロンプト組み立て | 場面・文体・宛先が正しく埋め込まれるか。未入力欄が「undefined」等にならないか |
| 宛名の組み立て | 会社名・部署・氏名・敬称の有無の組み合わせで正しい宛名行になるか |
| 署名の連結 | 本文末尾に署名が1回だけ付くか。署名未設定なら付かないか |
| Gmail URL 生成 | エスケープが正しいか。長さ超過を判定できるか |
| 履歴の保持 | 100件を超えたら古いものから消えるか。同一宛先が重複しないか |
| APIエラーの分類 | ステータスコードから正しいメッセージ種別を返すか |

API 呼び出し・Outlook 下書き・ブラウザ起動は**手動確認**とする。
