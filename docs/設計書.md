# 俺の秘書子 — 設計書

最終更新: 2026-09-04

## 1. 概要

### 目的
汎用的な業務能率化デスクトップアプリ。特定の会社・特定業務に依存しない機能を、
必要に応じて追加していける「機能プラグイン方式」で作る。

第1機能は **メール文面作成**。Claude API を使い、場面（御礼・謝罪・日程調整など）と
宛先・件名・一言メモを入力するだけで、その場面にふさわしいビジネスメールの文面を生成し、
Outlook または Gmail の**下書き**として開く。

### 既存アプリ TaskHelper との関係
TaskHelper（人事労務業務に特化した Electron アプリ）を**構成の参考元**とする。
以下を流用する（TaskHelper 側のファイルは一切変更しない）。

| 流用元 | 用途 |
|---|---|
| `electron/main.js` / `preload.js` | Electron の起動・IPC の骨格 |
| `src/main/settings.js` | 設定の永続化パターン |
| `src/main/outlook-send.ps1` | Outlook COM 操作（**送信ではなく下書き表示**に改造） |
| `package.json` の `build` セクション | electron-builder（nsis インストーラ / portable exe）設定 |

TaskHelper 固有の業務ロジック（有休・出勤率・残業・名簿など）は**一切持ち込まない**。

### 技術スタック
- Electron 33 + Node.js（TaskHelper と同一）
  - app-package-flow の既定である Python + Tkinter からの逸脱。理由は Outlook 連携資産の
    流用と UI 表現力。ユーザー承認済み。
- Claude API（Anthropic Messages API）
- electron-builder（nsis インストーラ + portable exe）
- テスト: `node --test`（Node 標準テストランナー）

### リポジトリ
https://github.com/kamaboko3473150buta-ux/orenohisyoko （**公開リポジトリ**）

公開リポジトリであるため、APIキー・宛先・作成した文面などの機密情報は
**リポジトリに一切含めない**。これらはすべて実行 PC のユーザープロファイル配下に保存する。

## 3. 機能一覧

| ID | 機能 | 内容 |

| F-01 | 機能選択メニュー | トップで機能を選ぶ。将来の追加を前提としたカード形式 |

## 4. データ設計

### 4-1. 保存場所
`%APPDATA%\ore-no-hishoko\`（Electron の `app.getPath('userData')`）

exe にもリポジトリにも含まれない。別PCにアプリを配っても中身は引き継がれない。

### 4-2. `settings.json`

```json
{
  "apiKeyEncrypted": "<base64: safeStorage で暗号化した文字列>",
  "signature": "株式会社△△ 総務部\n松原 太郎\nTEL: ...",
  "defaultTone": "formal_external",
  "defaultMailer": "outlook"
}
```

APIキーは Electron の `safeStorage`（Windows の DPAPI）で暗号化して保存する。
`safeStorage` が使えない環境では、その旨を警告したうえで平文保存にフォールバックする。

### 4-3. `contacts.json`（宛先履歴）

```json
[
  {
    "email": "yamada@example.com",
    "company": "株式会社○○",
    "department": "営業部",
    "name": "山田 太郎",
    "honorific": "様",
    "lastUsedAt": "2026-09-04T10:00:00.000Z"
  }
]
```

同一メールアドレスは上書き。最終使用日時の降順で最大100件保持。

### 4-4. `history.json`（文面履歴）

```json
[
  {
    "id": "2026-09-04T10:00:00.000Z",
    "scene": "thanks",
    "tone": "formal_external",
    "to": "yamada@example.com",
    "subject": "お打ち合わせの御礼",
    "body": "……",
    "createdAt": "2026-09-04T10:00:00.000Z"
  }
]
```

新しい順に最大100件。超えたら古いものから捨てる。

### 4-5. Claude API 呼び出し

公式 SDK **`@anthropic-ai/sdk`** を使う（生の HTTP は書かない）。Electron のメインプロセス
（Node 側）から呼ぶ。レンダラー（画面）側には APIキーを一切渡さない。

| 項目 | 値 | 理由 |
|---|---|---|
| モデル | `claude-opus-5` | 日本語ビジネス文書の品質を優先。`src/main/claude.js` の定数1行で変更できる |
| `max_tokens` | 4000 | メール1通には十分。切り詰められる心配がない |
| `output_config.effort` | `low` | メール作成は単純なタスク。低くすることで応答が速く・安くなる |
| `thinking` | 指定しない | Opus 5 は既定で adaptive。短文生成では指定不要 |
| タイムアウト | 60秒 | SDK の `timeout` オプション（ミリ秒指定なので `60000`） |

- system プロンプト: 「日本のビジネスメールを書く秘書」としての役割・出力形式の指示
- user プロンプト: 場面・宛先・件名・一言メモ・文体を埋め込んだテンプレート
- 出力形式: **本文のみのプレーンテキスト**（前置き・解説・マークダウンは出力させない）。
  Opus 5 以降では assistant プレフィル（返答の書き出しを指定する手法）が使えないため、
  出力形式の制御は system プロンプトで行う。
- 署名はアプリ側で本文末尾に連結する（AI には書かせない）
- レスポンスは `response.content` の配列から `type === 'text'` のブロックを取り出す
- `response.stop_reason === 'refusal'` の場合は本文が空になるため、
  「この内容では文面を作成できませんでした。書き方を変えてお試しください」と表示する

**費用の目安**: 1通あたり入力約1,000トークン・出力約800トークン。
Opus 5 は入力 $5／出力 $25（各100万トークン）なので、**1通あたりおよそ4円**。

### 4-6. Gmail 下書きの開き方

```
https://mail.google.com/mail/?view=cm&fs=1&to=<宛先>&su=<件名>&body=<本文>
```

各値は `encodeURIComponent` でエスケープし、`shell.openExternal` で既定ブラウザに渡す。

URL 全長が 8000 文字を超える場合は、ブラウザ側で切れる恐れがあるため、
本文をクリップボードにコピーしたうえで宛先・件名だけの URL を開き、その旨を画面に表示する。

### 4-7. Outlook 下書きの開き方

`draft-outlook.ps1` に JSON（宛先・件名・HTML本文）を渡し、Outlook COM で
`CreateItem(0)` → プロパティ設定 → **`.Display()`**（送信はしない）。
TaskHelper の `outlook-send.ps1` から `.Send()` を除いた形。

## 5. エラー処理方針

| 状況 | 画面の挙動 |
|---|---|
| APIキー未設定 | 「文面を作成する」を押した時点で案内を出し、設定画面へ誘導する |
| APIキーが無効（401） | 「APIキーが正しくないようです。設定を確認してください」 |
| 利用上限・残高不足（429/402） | 「Anthropic 側の利用上限に達している可能性があります」 |
| 通信できない | 「インターネットに接続できませんでした」＋再試行ボタン |
| API がタイムアウト（60秒） | 「時間内に応答がありませんでした」＋再試行ボタン |
| 必須項目が空（宛先メール・件名・メモのいずれか） | 生成前に該当欄を赤枠で示し、API は呼ばない |
| Outlook がインストールされていない | 「Outlook が見つかりません」＋ Gmail で開く／コピーする を提案 |
| Gmail の URL が長すぎる | 本文をコピーしたうえで宛先・件名のみの作成画面を開き、貼り付けを案内 |
| 設定ファイルが壊れている | 既定値で起動し、「設定を読み込めなかったため初期化しました」と表示 |

APIキーはログにも画面のエラー文にも**絶対に出力しない**。

## 6. 制約・注意事項

- **Windows 専用**。Outlook 連携は Windows の Outlook classic デスクトップ版が前提。
- **送信はしない**。アプリは下書きを開くところまで。送信操作は必ず人間が行う。
- **API 利用料はユーザー負担**。1通あたりおおむね数円以下だが、無制限ではない。
- **公開リポジトリ**のため、APIキー・実在の宛先・実際の文面をコミットしない。
  `.gitignore` で `dist/`・`node_modules/`・`*.log`・`.env` を除外する。
- 生成された文面は**必ず人間が確認してから送る**。AI が事実を取り違える可能性がある。
- コード署名をしていないため、配布先PCで SmartScreen 警告が出る（「詳細情報」→「実行」で起動可）。

## 7. テスト方針

外部（API・Outlook・ブラウザ）に依存しないロジックだけを `node --test` で自動テストする。

| 対象 | 確認内容 |
|---|---|
| プロンプト組み立て | 場面・文体・宛先が正しく埋め込まれるか。未入力欄が「undefined」等にならないか |
| 宛名の組み立て | 会社名・部署・氏名・敬称の有無の組み合わせで正しい宛名行になるか |
| 署名の連結 | 本文末尾に署名が1回だけ付くか。署名未設定なら付かないか |
| Gmail URL 生成 | エスケープが正しいか。長さ超過を判定できるか |
| 履歴の保持 | 100件を超えたら古いものから消えるか。同一宛先が重複しないか |
| APIエラーの分類 | ステータスコードから正しいメッセージ種別を返すか |

API 呼び出し・Outlook 下書き・ブラウザ起動は**手動確認**とする。
